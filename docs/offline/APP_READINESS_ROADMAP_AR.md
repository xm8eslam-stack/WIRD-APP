# خارطة جاهزية وِرد للعمل دون إنترنت والتحول إلى تطبيق

**التاريخ:** 12 نوفمبر 2026

## الهدف النهائي
أن يستطيع المستخدم تثبيت وِرد وفتحه دون اتصال بعد التجهيز الأول، وقراءة القرآن والمحتوى اليومي الأساسي، وإدارة تقدمه محليًا، والاستماع إلى ما نزّله أو تم تخزينه بصورة مشروعة، ثم استعادة الاتصال ومزامنة التغييرات بأمان. بعد إثبات ذلك، نجهز إصدار تطبيق قابل للتثبيت مع أقل إعادة كتابة ممكنة.

## تصنيف كل ميزة
| الحالة | معناها | مثال |
|---|---|---|
| مدمج Bundled | يعمل من أول فتح دون شبكة | نص القرآن المحلي والبيانات الأساسية |
| مجهز Offline | يعمل بعد تنزيل حزمة التطبيق/المحتوى | شاشات lazy-loaded وملفاتها |
| مخزن سابقًا | يعمل إذا سبق جلب النسخة والتحقق منها وما زالت صالحة | تفسير أو حديث تم فتحه سابقًا |
| تخزين انتهازي | قد يعمل مؤقتًا دون ضمان الاحتفاظ | مقطع الصوت التالي أو صفحة زارها المستخدم |
| يتطلب الإنترنت | يحتاج اعتمادًا خارجيًا أو محتوى غير محفوظ | تسجيل الدخول وAPI حي |

يجب أن تظهر الحالة بوضوح، ولا يجوز عرض ميزة شبكية على أنها Offline لمجرد أن واجهتها تفتح.

## خطة التنفيذ المتوازية

### A — حصر كامل للتطبيق
- استخراج جميع المسارات من router والقائمة والروابط العميقة.
- ربط كل مسار بالـ lazy chunks والصور والخطوط وملفات JSON والبيانات والخدمات التي يستدعيها.
- حصر الأفعال: قراءة، حفظ، تعديل، بحث، تشغيل صوت، تنزيل، تصدير، تسجيل دخول، نسخ احتياطي، مزامنة.
- تسجيل المصدر والترخيص والحجم وسياسة التخزين والانتهاء والبديل Offline لكل عنصر.

### B — PWA وService Worker
- التحقق من install/activate/controller/update وفتح التطبيق بعد إعادة تشغيل المتصفح.
- ضمان شمول كل الشاشات الأساسية وملفاتها في حزمة Offline، لا ملفات البداية فقط.
- فحص الملفات العامة public والـ fonts الخارجية وملفات الصور والبيانات التي لا تظهر في manifest الحالي.
- اختبار تنزيل الحزمة واستكمالها بعد الانقطاع، وصدق عداد الملفات، وتحديث cache version دون حذف المحتوى المثبت للمستخدم.
- عزل cache التطبيق العام عن cache المستخدم وعن الملفات الصوتية المثبتة.

### C — البيانات المحلية
- إعداد خريطة بكل localStorage وIndexedDB وCache Storage والـ journals/outbox/inbox.
- اختبار بقاء التقدم والبيانات بعد إغلاق التطبيق وإعادة تشغيل الجهاز/المتصفح.
- التحقق من guest مقابل UID، وتبديل الحساب، وتسجيل الخروج، وعدم تسريب بيانات مستخدم إلى آخر.
- استخدام معاملات IndexedDB فقط حيث نحتاج ذرية فعلية؛ أي ترحيل يحتاج نسخًا احتياطيًا واختبارات توافق واسترجاع.

### D — القرآن والعبادات الأساسية
- النص القرآني المحلي الموثق هو المرجع؛ لا يتم استبداله أو توليد بديل له.
- إتاحة الأذكار اليومية والمحتوى الأساسي محليًا مع مصدر/نسخة واضحين.
- حفظ موضع القراءة والتقدم والعلامات والإعدادات محليًا.
- البحث المحلي يعمل على الفهارس المضمنة فقط؛ البحث الذي يعتمد على خادم يوضح حاجته للاتصال.
- الصلاة والقبلة: تحديد ما يمكن حسابه محليًا من إحداثيات/إعدادات محفوظة، وما يتطلب إذن موقع أو خدمة خارجية. لا يُعرض وقت صلاة قديم باعتباره محدثًا.

### E — التفسير والحديث والرقية
- إظهار النسخ التي تم جلبها والتحقق منها مسبقًا فقط، مع بيان تاريخ/مصدر التخزين عند الحاجة.
- عند عدم وجود نسخة محلية، إظهار أن الاتصال مطلوب؛ لا AI-generated fallback للنصوص الدينية.
- نص الرقية من بيانات وِرد المحلية الموثقة؛ فهرس أو مكتبة خارجية غير متاحة Offline ما لم تُحفظ وتُراجع حقوقها.

### F — الصوت والتنزيلات
- الفصل بين cache انتهازي محدود وبين تنزيلات المستخدم المثبتة.
- السماح بالتنزيل فقط من مصدر وقارئ وbitrate مصرح بهم؛ إعادة التحقق من الشروط عند التنفيذ والإطلاق.
- منع EveryAyah من التخزين Offline حتى يثبت حق واضح.
- تنزيل قابل للاستكمال والإلغاء وإعادة المحاولة والحذف، مع تقدير مساحة، وفحص حجم/نوع/استجابة كل ملف.
- لا تدخل الملفات الصوتية في Firebase sync أو النسخ الاحتياطية أو بيانات الحساب.

### G — تجربة Offline
- مركز واحد يعرض حالة Service Worker، نسخة الحزمة، عدد الملفات، المساحة، التخزين الدائم، التنزيلات، والميزات التي تحتاج اتصالًا.
- حالات واضحة: لم يبدأ، جارٍ، مكتمل، ناقص، فشل، مساحة غير كافية، متصفح غير مدعوم.
- الاحتفاظ بموضع القراءة والمدخلات عند انقطاع الشبكة، وعدم فقد أي تغيير محلي.
- إمكانية إدارة المحتوى وتنظيف الملفات غير المثبتة دون حذف تقدم المستخدم.

### H — الاستعداد كتطبيق
- المرحلة الأولى: PWA قابلة للتثبيت وتجربة متسقة على Android وiOS وDesktop.
- بعد نجاح Offline web: مقارنة Capacitor وAndroid Trusted Web Activity وخيارات native حسب الصوت بالخلفية والإشعارات والتخزين والروابط العميقة وسياسات المتاجر والصيانة والتكلفة.
- لا نضيف native wrapper أو plugins قبل تحديد الاحتياج واختبار PWA؛ لا نكرر بناء النظام مرتين.
- إعداد دورة إصدار وتحديث، وسياسة خصوصية، وسلوك عند فقد الاتصال، واختبارات أجهزة فعلية.

## مصفوفة القبول قبل الإعلان عن الجاهزية
- فتح جديد ثم تجهيز الحزمة بالكامل.
- فتح كل المسارات الأساسية بعد فصل الإنترنت.
- إغلاق المتصفح/التطبيق وإعادة فتحه في وضع الطيران.
- قراءة القرآن والبحث المحلي وحفظ موضع القراءة وتقدم العبادات.
- تشغيل صوت محفوظ، وفشل واضح للصوت غير المحفوظ.
- عرض تفسير/حديث محفوظ، وإظهار حالة الاتصال للمحتوى غير المحفوظ.
- استكمال تنزيل منقطع وإلغاء تنزيل وحذف عنصر والتحقق من المساحة.
- تحديث Service Worker دون فقد التنزيلات المثبتة أو التقدم المحلي.
- تبديل Guest/حساب A/حساب B دون تسريب بيانات.
- إعادة الاتصال: إرسال التغييرات مرة واحدة، ومعالجة التعارض دون إسقاط التقدم المحلي.
- اختبارات هاتف وكمبيوتر وقارئ شاشة وRTL وتقليل الحركة.

## ممنوعات وحدود
- لا أسرار أو رموز دخول أو ردود API خاصة داخل cache عام.
- لا حذف تلقائي لمحتوى اختاره المستخدم Offline.
- لا اعتماد على ساعة العميل لحسم التعارضات.
- لا مزامنة لملفات الصوت ولا تفعيل sync flags أو تغيير Firestore rules دون موافقة صريحة وبوابات مستقلة.
- لا وعود بعمل كل الخدمات الخارجية دون إنترنت.
- لا اعتماد على نجاح CI وحده لإعلان Offline readiness؛ يجب اختبار متصفح وجهاز فعلي.

## ترتيب التنفيذ
ابدأ بالحصر والتدقيق والاختبارات، ثم سد فجوات حزمة Offline وPWA، ثم تحسين التخزين المحلي والمحتوى والصوت والواجهة، ثم اختبار الاسترداد والمزامنة، وأخيرًا تقييم wrapper التطبيق. يمكن تنفيذ مسارات مستقلة بالتوازي، لكن لا تُتجاوز تبعيات الحقوق أو البيانات أو أمان المزامنة.
