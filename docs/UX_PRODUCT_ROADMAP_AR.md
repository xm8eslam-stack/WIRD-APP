# خارطة تطوير تجربة وِرد

## مبادئ التصميم

- القرآن هو المرجع النصي الوحيد داخل التطبيق. لا تُصحّح الآيات يدويًا ولا تستبدل النص بمصدر آخر وقت التشغيل.
- فصل القراءة والختمة عن الحفظ والمراجعة في التخزين والعدادات والسجل.
- واجهة عربية RTL مريحة على الهاتف، بأهداف لمس واضحة، وحالة تحميل وخطأ معلنتين، ودعم لوحة المفاتيح وقارئات الشاشة.
- كل حديث أو تفسير يظهر مع المصدر والكتاب ورقم الموضع؛ لا تنشأ علاقة بين آية وحديث بالبحث الدلالي أو التخمين.
- الاستفادة من بنية الأفكار المفتوحة، مع مراجعة الترخيص وعدم نسخ بيانات أو شيفرة دون حق واضح.

## مراحل التنفيذ

### 1. سلامة المحتوى القرآني — أولوية قبل أي توسع

- التحقق من 114 سورة و6,236 آية وترقيم الآيات والصفحات والأجزاء والأحزاب.
- إبقاء مقارنة Tanzil الحرفية المستقلة بوصفها بوابة الإطلاق، وتسجيل بصمة الملف وتاريخ التدقيق والفروق التفصيلية.
- إضافة فحص مرئي/آلي لأمثلة Unicode والتشكيل وعلامات الوقف والآية التي أبلغ عنها المستخدم.
- مراجعة كل مصدر بيانات مشتق وإسناده وترخيصه؛ لا تُجرى أي تغييرات للنص إلا من المصدر الرسمي وبمسار توليد قابل لإعادة الإنتاج.

### 2. القراءة بالمصحف والختمات

- قارئ صفحات مصحف المدينة الورقي: تقليب باللمس وأزرار ولوحة مفاتيح، انتقال للسورة والجزء والصفحة، علامات مرجعية، قارئ وسرعة، تفسير الآية.
- ختمة قراءة مستقلة: بدء/استمرار/إعادة بدء، صفحات مقروءة يدويًا، نسبة تقدم، وآخر صفحة متبقية. لا تُحسب الصفحة بمجرد فتحها أو تشغيل الصوت.
- المرحلة الحالية تضيف تقدم ختمة محليًا منفصلًا وزر تسجيل الصفحة ومؤشر تقدم، وتدعم السحب للهاتف وتقليبًا بصريًا خفيفًا مع احترام تقليل الحركة.

### 3. جلسات الحفظ والمراجعة

- إظهار التفسير بجوار الآية الحالية في الوضعين، مع اختيار الكتاب والتعامل مع التحميل والفشل وتبديل الآية.
- ربط جلسة المراجعة بالمقطع المختار وإظهار تقدمه ونقاط الضعف؛ إبقاء الإكمال والتسجيل في خدمات السجل الحالية.
- إبقاء سرعة الصوت وتكراره تحت تفضيلات واضحة، وإيقاف الوسائط والمؤقتات عند تغيير الآية أو الخروج.
- المرحلة الحالية تضيف لوحة تفسير مشتركة لجلسة الحفظ والمراجعة، تتبدل بحسب الآية النشطة، وقسم أحاديث اختياريًا مبنيًا على الإحالة الصريحة للآية.

### 4. الأحاديث المرتبطة بالآيات

- المصدر المرشح: Quran Foundation Hadith References API، لأنها توثق مراجع حديثية مرتبطة بمفتاح الآية صراحةً، وتوفر استرجاع المراجع والنصوص.
- أُضيف مسار خادمي محمي يستعمل `QF_CLIENT_ID` و`QF_CLIENT_SECRET` و`QF_CONTENT_SCOPE` الاختياري و`QF_ENV=prelive` الاختياري، ويطلب التقييم العربي الصريح «صحيح» فقط. المفاتيح لا تخرج للمتصفح، ولم تُضف أو تُغير أي أسرار إنتاجية. يلزم تهيئة وصول خادمي مصرح به ومراجعة الترخيص والتغطية قبل تفعيله في النشر.
- لا يُعرض الحديث كشرح للآية إلا إذا أعاد المصدر ربطًا صريحًا موثقًا؛ ولا تُستخدم مطابقة كلمات أو استنتاج آلي. عند عدم وجود نتيجة، لا يظهر محتوى بديل.
- التكامل الحالي مقيد بالإحداثيات والمهلة والحجم ومعدل الطلب، يتحقق من مخطط الرد ودرجة الحديث والتخريج، ويعرض بطاقة اختيارية في الجلسات ومصحف القراءة. لم يُختبر اتصال خارجي حقيقي لغياب إعداد مفاتيح الخدمة.

## التحقق قبل الإطلاق

- اختبارات خدمات التخزين والمجال منفصلة عن اختبارات مكونات الواجهة.
- اختبار تكامل: بدء جلسة حفظ/مراجعة، تبديل الآية، فشل طلب التفسير وإعادة المحاولة، خروج وتنظيف الطلب.
- اختبار ختمة: إنشاء مستقل، قراءة الصفحة نفسها مرتين، حدود 1–604، إعادة التحميل، إعادة البدء، والتأكد من عدم مساس سجل الحفظ.
- اختبار الهاتف: سحب الصفحة، تكبير الخط، مناطق اللمس، RTL، قارئ الشاشة، تقليل الحركة، وألا يسجل فتح الصفحة قراءتها تلقائيًا.
- بوابات الإصدار في المستودع: `npm test`، `npm run lint`، `npm run build`، فحوص القواعد والدخان المتاحة وCI على SHA النهائي.

## مرجع التعلم من مشاريع ومصادر قائمة

- مشروع Ummah Library يشرح فصل مجموعات البيانات والتوثيق وإعادة التوليد، ويقدم أوضاع قراءة متعددة. يُستفاد منه كمرجع معماري فقط؛ ترخيص AGPL-3.0 مختلف ويُراجع قبل أي اقتباس أو نسخ.
- مكتبة StPageFlip مرجع ممكن لتجربة قلب الصفحات (MIT)، لكن يجب اختبار قارئ الشاشة، النص التفاعلي العربي، التحميل الكسول، والحركة المخفّضة قبل إدخال اعتماد جديد.
- Tanzil يشترط إبقاء النص كما هو وإسناد المصدر وربطه؛ لذلك يبقى نص المشروع الحالي المرجع الوحيد ولا تُنسخ تعديلات يدوية.
- API حديث Quran Foundation هو خيار علاقة الآية بالحديث، لكنه خادمي ويتطلب بيانات اعتماد. يلزم تأمين الاعتماد والتحقق من الترخيص/التخريج قبل تفعيله.

## 6. السيرة النبوية والصحابة — كتاب «حكاية السيرة»

هذه ميزة تعليمية أساسية مخططة، وليست جزءًا منفذًا من الواجهة الحالية. التجربة المطلوبة **كتاب تاريخي تفاعلي متصل**: أجزاء كبرى، ثم فصول مترابطة، ثم مشاهد سردية. ليست قائمة دروس قصيرة ولا سلسلة بطاقات واختبارات. القراءة المتصلة هي التجربة الافتراضية، والتعلّم التفاعلي طبقة اختيارية حول النص.

- لا تعتمد على API واحدة بوصفها مرجعًا نهائيًا؛ كل معلومة وسؤال وإجابة لها مصدر وحالة مراجعة.
- لا نشر تلقائي لمحتوى API ولا توليد AI لروايات تاريخية أو أحاديث أو اقتباسات أو أسئلة منشورة.
- توضح التواريخ التقريبية والروايات المختلف فيها، وتستبعد المسائل غير المحسومة من أسئلة الحقيقة القطعية.
- لا تجسيد بصري للنبي ﷺ أو الصحابة؛ تستخدم الخرائط الموثقة والمناظر والزخارف والرسوم المجردة.
- يبدأ العمل باختبار المصادر والتغطية العربية والترخيص والخصوصية والحدود والتخزين دون اتصال.
- يكون التقدم محليًا أولًا، وتُزامن حالة القراءة المختصرة فقط؛ لا تُنسخ كتب أو محتويات عامة إلى Firestore لكل مستخدم.
- تظل تجربة الحفظ والمراجعة القرآنية هي الأولوية الأولى.
- المرجع التحريري ومخطط البيانات ودورة اعتماد النص في [خطة تعلم السيرة النبوية والصحابة](./SEERAH_LEARNING_PLAN_AR.md) §§16–17.

### 6.1 بنية الكتاب ورحلة القارئ

- صفحة دخول للكتاب تعرض فكرته، نطاقه، آخر موضع قراءة، وتقدمًا مفهومًا بالأجزاء والفصول؛ لا تبدأ باختبار أو شبكة دروس.
- صفحة الجزء تقدم تمهيدًا يشرح المرحلة وسياقها، ثم فهرس الفصول وتسلسلها.
- صفحة الفصل تعرض عنوانًا واضحًا ومدخلًا قصيرًا، ثم نصًا متصلًا مقسمًا إلى مشاهد بعناوين هادئة. لا تتحول كل فقرة إلى بطاقة منفصلة.
- نهاية الفصل تقدم خلاصة موجزة وجسرًا معرفيًا إلى الفصل التالي، مع خيار «تابع الفصل التالي» وخيار العودة إلى الفهرس.
- الفهرس الجانبي/المنبثق يسمح بالقفز إلى جزء أو فصل أو مشهد دون فقد موضع القراءة، ويبين موضع القارئ الحالي.
- لا تُعرض أرقام تقدم توحي بأن قراءة النص تعني حفظه أو إتقانه؛ التقدم هنا تقدم قراءة فقط.

### 6.2 أوضاع القراءة وعناصر التحكم

- **قراءة متصلة:** نص مريح بعرض مناسب، خط وتباعد قابلان للتعديل، وضع ليلي، حفظ موضع تلقائي، انتقال هادئ بين المشاهد. هذا هو الوضع الافتراضي.
- **قراءة وتعلّم:** نفس النص ونفس ترتيب المشاهد، مع فتح السياق والشخصيات والأماكن والخط الزمني عند الطلب، دون تحويل السرد إلى شرائح.
- شريط قراءة بسيط: اسم الجزء/الفصل، موضع المشهد، تقدّم الفصل، فهرس، حفظ علامة، إعدادات النص.
- حفظ الموضع بعد تغيّر الفصل/المشهد أو مغادرة القارئ، مع استعادة آمنة بعد إعادة التحميل. تخزين محلي أولًا؛ المزامنة السحابية لاحقًا وبعد بوابة مستقلة.
- لا autoplay صوتي أو مرئي، ولا popups تقطع السرد، ولا إجبار على إكمال سؤال كي يواصل القارئ.
- عناصر التحكم قابلة للوصول بلوحة المفاتيح وقارئ الشاشة، وتدعم RTL وتقليل الحركة.

### 6.3 السياق دون قطع الحكاية

- تمييز أسماء الشخصيات والأماكن والأحداث المرتبطة بسجل موثق، ويكون فتح البطاقة عند النقر/اللمس أو من زر واضح، لا عبر تفاعل hover فقط.
- بطاقة السياق تعرض تعريفًا موجزًا، زمنًا/مكانًا عند ثبوتهما، صلة الموضوع بالفصل، ومراجع قابلة للفتح. لا تضيف سيرة غير موثقة.
- الخريطة والخط الزمني لوحتان مساعدتان يمكن فتحهما وإغلاقهما، وتعرضان درجة يقين المكان والتاريخ. لا تضعان بيانات تقريبية في موضع الحقيقة القطعية.
- المراجع متاحة من علامة صغيرة مرتبطة بكتلة النص أو من لوحة «مصادر هذا الفصل». فتح المرجع لا يغيّر موضع القراءة.
- عند وجود روايات مختلفة، تظهر ملاحظة تحريرية واضحة ومتناسبة مع أهمية الخلاف، لا تكدسًا من الحواشي وسط الفقرة.

### 6.4 حفظ التقدم والخصوصية

- الحد الأدنى للتقدم: آخر جزء/فصل/مشهد، anchor داخل النص، نسبة تمرير تقريبية، آخر وقت تحديث، وإصدار المحتوى.
- العلامات المرجعية مرتبطة بـcontentVersion وanchor ثابت؛ عند تغير النص تُحاول مطابقة anchor وتعرض fallback بدل نقل المستخدم لموضع خاطئ.
- الملاحظات الشخصية محلية افتراضيًا، ولا ترفع إلى Firestore دون سياسة واضحة وموافقة منفصلة.
- لا يخزن Firestore نص الكتاب لكل مستخدم؛ المحتوى العام ثابت/موزع كحزمة محتوى معتمدة، والتقدم الشخصي فقط هو ما يمكن مزامنته لاحقًا.
- عند حذف الحساب أو فقدان الجهاز تُشرح حدود استعادة التقدم المحلي قبل تفعيل أي مزامنة.

### 6.5 حالات الواجهة ومعايير القبول

- حالات واضحة: تحميل الكتاب، فصل غير متاح، محتوى غير منشور/قيد المراجعة، خطأ في تحميل المراجع، عدم اتصال مع محتوى محلي متاح، وإصدار محتوى أحدث.
- فشل بطاقة أو API خارجية لا يمنع قراءة النص الأساسي ولا يغيره.
- قبول MVP يتطلب جزءًا افتتاحيًا وفصلًا متعدد المشاهد بمحتوى معتمد، قارئًا متصلًا، فهرسًا، حفظ واستعادة موضع القراءة، بطاقات سياق ومراجع لا تقطع السرد، ودعم RTL/إمكانية الوصول.
- اختبارات لازمة: استعادة موضع القراءة بعد reload/offline، التنقل بين الفصول، تحديث contentVersion، العلامات عند تغير النص، قارئ الشاشة، تكبير الخط، الهاتف، وفشل مصدر خارجي.
- قائمة دروس أو واجهة اختبارات أو بيانات API خام لا تحقق القبول. الفصل الهيكلي المقترح في §17.4 من خطة السيرة ليس محتوى تاريخيًا منشورًا ولا يُستخدم كبيانات اختبار واقعية.

## 7. ترتيب تنفيذ «حكاية السيرة»

1. تثبيت UX وعقد المحتوى والـanchors وإصدار المحتوى.
2. فحص بنية المشروع الحالية وتحديد هل توجد مكونات قارئ/نظام توجيه/تخزين يمكن إعادة استخدامها دون تكرار.
3. تنفيذ نموذج واجهة ببيانات placeholder موسومة بوضوح، دون إدخال تاريخ غير موثق.
4. بناء قارئ متصل وفهرس وحفظ موضع القراءة واختبارات الوحدة/التكامل.
5. ربط سجل محتوى معتمد فقط بعد اكتمال claims والمراجع والمراجعات وحقوق العرض.
6. إضافة بطاقات السياق والخرائط والخط الزمني ثم أدوات التعلم الاختيارية.
7. لا نشر ولا مزامنة سحابية ولا تفعيل API قبل بوابات الجودة والحقوق والموافقة المطلوبة.
