# خارطة تطوير تجربة وِرد

## مبادئ التصميم

- القرآن هو المرجع النصي الوحيد داخل التطبيق. لا تُصحّح الآيات يدويًا ولا تستبدل النص بمصدر آخر وقت التشغيل.
- فصل القراءة والختمة عن الحفظ والمراجعة في التخزين والعدادات والسجل.
- واجهة عربية RTL مريحة على الهاتف، بأهداف لمس واضحة، وحالة تحميل وخطأ معلنتين، ودعم لوحة المفاتيح وقارئات الشاشة.
- كل حديث أو تفسير يظهر مع المصدر والكتاب ورقم الموضع؛ لا تنشأ علاقة بين آية وحديث بالبحث الدلالي أو التخمين.
- الاستفادة من بنية الأفكار المفتوحة، مع مراجعة الترخيص وعدم نسخ بيانات أو شيفرة دون حق واضح.

## مراحل التنفيذ

### 1. سلامة المحتوى القرآني — أولوية قبل أي توسع

- التحقق من 114 سورة و6,236 آية وترقيم الآيات والصفحات والأجزاء والأحزاب.
- إبقاء مقارنة Tanzil الحرفية المستقلة بوصفها بوابة الإطلاق، وتسجيل بصمة الملف وتاريخ التدقيق والفروق التفصيلية.
- إضافة فحص مرئي/آلي لأمثلة Unicode والتشكيل وعلامات الوقف والآية التي أبلغ عنها المستخدم.
- مراجعة كل مصدر بيانات مشتق وإسناده وترخيصه؛ لا تُجرى أي تغييرات للنص إلا من المصدر الرسمي وبمسار توليد قابل لإعادة الإنتاج.

### 2. القراءة بالمصحف والختمات

- قارئ صفحات مصحف المدينة الورقي: تقليب باللمس وأزرار ولوحة مفاتيح، انتقال للسورة والجزء والصفحة، علامات مرجعية، قارئ وسرعة، تفسير الآية.
- ختمة قراءة مستقلة: بدء/استمرار/إعادة بدء، صفحات مقروءة يدويًا، نسبة تقدم، وآخر صفحة متبقية. لا تُحسب الصفحة بمجرد فتحها أو تشغيل الصوت.
- المرحلة الحالية تضيف تقدم ختمة محليًا منفصلًا وزر تسجيل الصفحة ومؤشر تقدم، وتدعم السحب للهاتف وتقليبًا بصريًا خفيفًا مع احترام تقليل الحركة.

### 3. جلسات الحفظ والمراجعة

- إظهار التفسير بجوار الآية الحالية في الوضعين، مع اختيار الكتاب والتعامل مع التحميل والفشل وتبديل الآية.
- ربط جلسة المراجعة بالمقطع المختار وإظهار تقدمه ونقاط الضعف؛ إبقاء الإكمال والتسجيل في خدمات السجل الحالية.
- إبقاء سرعة الصوت وتكراره تحت تفضيلات واضحة، وإيقاف الوسائط والمؤقتات عند تغيير الآية أو الخروج.
- المرحلة الحالية تضيف لوحة تفسير مشتركة لجلسة الحفظ والمراجعة، تتبدل بحسب الآية النشطة، وقسم أحاديث اختياريًا مبنيًا على الإحالة الصريحة للآية.

### 4. الأحاديث المرتبطة بالآيات

- المصدر المرشح: Quran Foundation Hadith References API، لأنها توثق مراجع حديثية مرتبطة بمفتاح الآية صراحةً، وتوفر استرجاع المراجع والنصوص.
- أُضيف مسار خادمي محمي يستعمل `QF_CLIENT_ID` و`QF_CLIENT_SECRET` و`QF_CONTENT_SCOPE` الاختياري و`QF_ENV=prelive` الاختياري، ويطلب التقييم العربي الصريح «صحيح» فقط. المفاتيح لا تخرج للمتصفح، ولم تُضف أو تُغير أي أسرار إنتاجية. يلزم تهيئة وصول خادمي مصرح به ومراجعة الترخيص والتغطية قبل تفعيله في النشر.
- لا يُعرض الحديث كشرح للآية إلا إذا أعاد المصدر ربطًا صريحًا موثقًا؛ ولا تُستخدم مطابقة كلمات أو استنتاج آلي. عند عدم وجود نتيجة، لا يظهر محتوى بديل.
- التكامل الحالي مقيد بالإحداثيات والمهلة والحجم ومعدل الطلب، يتحقق من مخطط الرد ودرجة الحديث والتخريج، ويعرض بطاقة اختيارية في الجلسات ومصحف القراءة. لم يُختبر اتصال خارجي حقيقي لغياب إعداد مفاتيح الخدمة.

## التحقق قبل الإطلاق

- اختبارات خدمات التخزين والمجال منفصلة عن اختبارات مكونات الواجهة.
- اختبار تكامل: بدء جلسة حفظ/مراجعة، تبديل الآية، فشل طلب التفسير وإعادة المحاولة، خروج وتنظيف الطلب.
- اختبار ختمة: إنشاء مستقل، قراءة الصفحة نفسها مرتين، حدود 1–604، إعادة التحميل، إعادة البدء، والتأكد من عدم مساس سجل الحفظ.
- اختبار الهاتف: سحب الصفحة، تكبير الخط، مناطق اللمس، RTL، قارئ الشاشة، تقليل الحركة، وألا يسجل فتح الصفحة قراءتها تلقائيًا.
- بوابات الإصدار في المستودع: `npm test`، `npm run lint`، `npm run build`، فحوص القواعد والدخان المتاحة وCI على SHA النهائي.

## مرجع التعلم من مشاريع ومصادر قائمة

- مشروع Ummah Library يشرح فصل مجموعات البيانات والتوثيق وإعادة التوليد، ويقدم أوضاع قراءة متعددة. يُستفاد منه كمرجع معماري فقط؛ ترخيص AGPL-3.0 مختلف ويُراجع قبل أي اقتباس أو نسخ.
- مكتبة StPageFlip مرجع ممكن لتجربة قلب الصفحات (MIT)، لكن يجب اختبار قارئ الشاشة، النص التفاعلي العربي، التحميل الكسول، والحركة المخفّضة قبل إدخال اعتماد جديد.
- Tanzil يشترط إبقاء النص كما هو وإسناد المصدر وربطه؛ لذلك يبقى نص المشروع الحالي المرجع الوحيد ولا تُنسخ تعديلات يدوية.
- API حديث Quran Foundation هو خيار علاقة الآية بالحديث، لكنه خادمي ويتطلب بيانات اعتماد. يلزم تأمين الاعتماد والتحقق من الترخيص/التخريج قبل تفعيله.
