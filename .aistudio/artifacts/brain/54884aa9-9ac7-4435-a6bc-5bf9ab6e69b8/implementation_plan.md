# الخطة الهندسية الشاملة لتنفيذ المزامنة السحابية الحقيقية (WIRD Cloud Sync)
## تكامل Firebase Authentication وCloud Firestore مع نظام IndexedDB المحلي المعتمد على سجل الأحداث

---

### أولاً: أهداف ومبادئ النظام الحاكم

1. **العمل بدون اتصال أولاً (Offline-First):**
   - التطبيق يعمل بنمط الزائر (Guest Mode) بكامل طاقته وميزاته دون إجبار المستخدم على التسجيل أو الاتصال بالإنترنت.
   - لا تتأثر نصوص المصحف الشريف (6,236 آية)، والتفاسير المعتمدة، وخوارزمية التكرار المتباعد SM-2 بأي عملية مزامنة.

2. **عزل البيانات والأمان الصارم (Zero-Trust & Attribute-Based Access Control):**
   - لكل مستخدم مسار معزول تماماً في Firestore:
     - `users/{uid}/{collection}/{documentId}` لمطابقة الإسقاطات.
     - `users/{uid}/events/{eventId}` لسجل الأحداث غير القابل للتعديل إطلاقاً (`allow update, delete: if false`).
   - لا يُسمح بأي قراءة أو كتابة سحابية إلا لحساب موثق البريد (`request.auth.token.email_verified == true`).
   - لا يوجد حذف فيزيائي من طرف العميل (`allow delete: if false`)؛ الحذف يتم عبر شواهد القبور (`tombstones`).

3. **الضمان التام للتشغيل على Vercel عبر GitHub:**
   - قراءة إعدادات Firebase من `firebase-applet-config.json` محلياً مع دعم كامل لمتغيرات البيئة (`VITE_FIREBASE_*`).
   - دعم التوافقية عند انعدام التهيئة أو فشل الاتصال، بحيث يظل التطبيق شغالاً بنسبة 100% كزائر بدون أي شاشة بيضاء أو استثناء غير معالج.
   - فحص واجتياز جميع الاختبارات (`npm test`) وفحوصات `npm run build` و`lint` قبل أي إنهاء للعمل.

### ثالثاً: مراحل التنفيذ خطوة بخطوة

#### 1. تهيئة طبقة Firebase وFirestore (`src/lib/firebase.ts`):
- دمج قراءة الإعدادات من `firebase-applet-config.json` المولد تلقائياً مع الاستمرار في دعم متغيرات البيئة `VITE_FIREBASE_*`.
- تهيئة مثيل Firestore مخصص لقاعدة البيانات المعينة (`ai-studio-wird-54884aa9-9ac7-4435-a6bc-5bf9ab6e69b8`).
- تصدير `db`، `auth`، `googleAuthProvider` مع دوال فحص الجاهزية.

#### 2. تحديث قواعد الأمان وبلوبرينت Firestore (`firestore.rules` و`firebase-blueprint.json`):
- إضافة مسار الأحداث غير القابلة للتعديل `users/{uid}/events/{eventId}`:
  - يُلزم بوجود: `schemaVersion`, `eventId`, `mutationId`, `uid`, `deviceId`, `occurredAtMs`, `eventType`, `payload`.
  - يمنع التعديل أو الحذف (`allow update, delete: if false`).
- إنشاء ملف `firebase-blueprint.json` لتوثيق الكيانات والمسارات وفق مواصفات المعيار.
- نشر القواعد فوراً عبر `DeployRules` RPC.

#### 3. بناء منسق المزامنة السحابية (`src/services/cloudSyncCoordinator.ts`):
- دورة عمل متكاملة:
  1. فحص المستخدم النشط والتأكد من تفعيل بريده الإلكتروني.
  2. قراءة الطفرات المعلقة من `localSyncOutbox` أو الأحداث من `IndexedDbSyncJournal`.
  3. رفع الوثائق والأحداث إلى Firestore باستخدام معرّفات فريدة تمنع التكرار (Idempotency).
  4. انتظار تأكيد الحفظ من Firestore ثم استدعاء `acknowledgeLocalMutation` ووضع علامة على الحدث كمؤكد.
  5. الاستماع للتغييرات البعيدة أو جلبها ومطابقتها دلالياً عبر `journalProjectionReplayer` دون محو أو تخريب سجلات التقدم.
  6. إدارة حالة المزامنة اللحظية (`idle`, `syncing`, `synced`, `offline`, `unverified`, `error`).

#### 4. حماية البيانات التجريبية وعدم تسريبها لحساب مسجل (PR #55):
- تعديل `handleLoadDemoData` بحيث يُمنع تحميل البيانات التجريبية لحساب مسجل فعلي دون موافقة أو عزل، وتوجيه البيانات للتسجيل عبر السجل المحلي إن لزم.

#### 5. تطوير واجهات المستخدم الخاصة بالمزامنة:
- إضافة شارة حالة المزامنة السحابية اللحظية في الرأس (`Header.tsx`):
  - أيقونة سحابة خضراء عند اكتمال المزامنة.
  - سهم دوار خفيف أثناء المزامنة.
  - شارة صفراء هادئة في وضع الزائر أو عند انتظار تفعيل البريد.
  - أيقونة أوفلاين لطيفة عند انقطاع الشبكة.
- إضافة قسم متكامل في `SettingsView.tsx`:
  - زر "مزامنة الآن" اليدوي.
  - توقيت آخر مزامنة ناجحة.
  - عدد العناصر في انتظار الرفع (إن وُجدت).
  - إمكانية نسخ معرف الحساب ومراجعة حالة الأمان.

#### 6. كتابة الاختبارات الشاملة والتحقق المزدوج:
- إضافة اختبارات وحدة للمزامنة السحابية `cloudSyncCoordinator.test.ts`.
- اختبار فحص قواعد Firestore `firestoreRules.test.ts`.
- تشغيل اختبارات المشروع `npm test` والتأكد من نجاح 100% من الاختبارات.
- إجراء `npm run build` و`compile_applet` و`lint_applet` للتحقق من جاهزية النشر على Vercel.
